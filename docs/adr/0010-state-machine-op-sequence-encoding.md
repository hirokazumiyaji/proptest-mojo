# ADR-0010: StateMachine トレイトと操作列の符号化で状態機械テストを行う

- 状態: Accepted
- 日付: 2026-09-30
- 関連: Issue #28、[specs/strategies.md](../specs/strategies.md) の状態機械テスト節

## 文脈

Hypothesis の `RuleBasedStateMachine` / `proptest-state-machine` に相当する、操作列を生成して不変条件を検証する仕組みが必要になった。制約は次の通り。

- property は `def(mut TestCase) raises` のクロージャであり（ADR-0004）、操作の選択も選択列で表さなければならない。そうしないと縮小と再現が選択列だけで成り立たない。
- ルールの集合は利用者ごとに異なるため、静的ディスパッチ（ADR-0003）に載る形で抽象化する必要がある。捕捉クロージャを struct に保持することはできない（ADR-0005）。
- 縮小ループは現在チャンク削除・ゼロ化・個別最小化だけであり（M1）、span パスは純粋関数として存在するがループに未接続である（M3）。操作列の縮小はこのループで効かなければならない。

## 決定

- `StateMachine` トレイト（`Movable`、`Deinitable`）を導入する。SUT とモデルは実装 struct のフィールドに持ち、`num_rules`（ルール数）、`run_rule`（引数の `tc.draw`・前提条件の `tc.assume`・両者への適用）、`check_invariants`（両者の比較）の 3 メソッドで表す。
- 操作列の駆動は `run_state_machine(machine, tc, max_ops=32)` に集約する。操作回数を `integers(0, max_ops)` で先に引き、その回数だけ「ルール番号の選択 → `run_rule` → `check_invariants`」を繰り返す。各操作を 1 つの span に包み、`step i: rule r` を `tc.note` する。
- 操作回数を先に引く方式を選ぶ。回数の最小化が末尾の操作を必ず削り、各操作が連続した選択の区間になるため、チャンク削除が中の操作を取り除ける。操作ごとの span は将来の `delete_spans` がそのまま使える。

## 検討した代替案

- ルールを comptime 関数のテーブルで登録する案: ルールごとに引数の型が異なるため、異種の集合を静的ディスパッチに載せられない。番号分岐の 1 メソッドに集約する方が単純。
- `lists` と同じ continue フラグ方式で操作を連ねる案: フラグとルールと引数で 1 操作が 3 選択以上になり、現在のチャンク幅（8・4・2・1）と整列しにくく、末尾を削るノブもない。回数を先に引く方式の方が現在の縮小ループと相性がよい。
- span パスを縮小ループに接続してから実装する案: M3 の作業であり、共有コアへの変更で並行 PR と競合する。本 issue の範囲外とし、span は記録だけして将来の接続に備える。

## 結果

- バグ入りスタックが `push(0), push(1), pop` の 3 操作（証明可能な最短）に縮小されることを、15 通りのシードで確認した。
- 1 操作の選択数が 3 以上の幅になると、現在のチャンク削除ではその操作を丸ごと取り除けない場合がある。引数を単一の `integers` 引きに保つ運用で回避し、`delete_spans` の接続（M3）で解消する。
- 左右順の個別最小化は `(1, 0)` のような局所最小に止まることがある（`lower_duplicates` 相当の M3 パスで解消予定）。テストは順序に依存しない表明にする。
