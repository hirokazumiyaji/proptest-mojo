# 縮小（Shrinking）

背景は [ADR-0002](../adr/0002-choice-sequence-based-shrinking.md) と [ADR-0008](../adr/0008-functional-core-imperative-shell.md)。

## 目標

失敗する選択列 `s` から、次を満たす `s'` を探す。

1. `s'` で property を実行すると `INTERESTING` になる。
2. shortlex で `s' < s`。

これを固定点（どのパスも改善できない）または予算切れまで繰り返す。
shortlex は整列順序なので、縮小は必ず停止する。

## 評価

候補の評価はランナーが行う（命令型シェル）。

```mojo
def evaluate(candidate: ChoiceSequence) -> Evaluation   # status と実際に消費した選択列
```

- 候補は **再生モード** の `TestCase` で実行する。prefix を使い切った後の選択は 0 になる。
- 採用するのは、評価結果の選択列（実際に消費した分）である。候補より短くなることがある。
候補は残りの評価予算をそのまま `limit` にせず、固定サイズの小さなバッチに分けて生成する。候補 1 個が選択列全体のコピーなので、既定の 5000 評価予算を全部渡すと 8192 choices の入力では1 つ目を確認する前に 4000 万ノード級を保持してしまう。
- 列挙パスは候補列を先に全部作るので、候補 1 個が選択列全体のコピーになる。選択列が 8192 choices に近いと全候補の生成だけで数 GB は必要になり、予算が 1 でも OOM する。よって列挙パスは `limit` を取り、縮小ループは残りの評価予算だけを渡す。
- キャッシュヒットは評価を消費しないので `limit` も消費してはならない。バッチが全てキャッシュヒットだった場合は `limit` を増やして取り直す。さもないと後続の候補に到達できず、予算が残ったまま固定点と報告してしまう。
- 同じ候補を二度評価しないよう、選択値の列をキーに評価結果をキャッシュする。
- 既定では任意の `INTERESTING` を採用する（失敗メッセージの一致は要求しない）。

## パスの形

縮小パスは関数型コアに属し、次の 2 種類がある。

| 種類 | シグネチャ（概念） | 例 |
|------|-------------------|----|
| 列挙パス | `(seq, spans) -> List[ChoiceSequence]` の純粋関数。候補を単純な順に返す | 削除、ゼロ化、並べ替え |

候補の順序は生成順ではなく結果の shortlex 順で決める。

また列挙パスは `limit` を取り、縮小ループが残りの評価予算を渡す。候補 1 個が選択列全体のコピーになるからで、`limit` が無いと選択列が 8192 choices 付近のときに全候補の生成だけで数 GB かかる。`zero_chunks` は候補を作る前に「その区間に 0 でない値があるか」を判定して Discard する。作ってから捨てると `zeroed` の全要素コピーが区間数分だけ起きるため。縮小ループは最初の interesting な候補を採用して先頭へ戻るため、区間長や開始位置順だと、同じ長さの候補の中で大きい値にコミットしてしまう（例: `[1..10]` から長さ 8 を削除すると `[9,10]`, `[1,10]`, `[1,2]` が出力されるが、正しくは `[1,2]`, `[1,10]`, `[9,10]` の順）。

順序づけは候補列同士を比べず、開始位置の添字だけを O(1) で比較して行う。同じノード数を削除する候補どうしは長さが等しいので、`start` と `size` の候補は `values[0:start] ++ values[start + size:]` の辞書順比較になり、これは `values` の Z 配列（`_shift_lcp`）で O(1) で判定できる。ゼロ化も同様に `_zero_runs` で最初の非ゼロ位置を O(1) で探す。候補列全体を比較すると 1 回 O(n)、候補が O(n) 本なので選択列が 8192 choices 付近になると実用上ハングした。並び替えは二分挿入ソートではなく bottom-up merge sort で行う。単調増加列では新しい候補が常に先頭へ入るため、挿入ソートの index 移動だけで O(n^2) になる。merge sort は index だけを O(n log n) で動かし、候補列は順序が決まってから生成する。
| 適応パス | 評価関数 `is_interesting` を引数で受け取る高階関数。二分探索のように前の結果で次の候補が決まる | 個々の値の最小化、値の再配分 |

適応パスも評価関数を注入するだけで、それ以外の副作用を持たない。テストでは評価関数に純粋な述語を渡す。

## パス一覧

上から順に適用し、いずれかが改善したら先頭に戻る。

| パス | 種類 | 内容 | 効果の例 | M |
|------|------|------|----------|---|
| `delete_chunks` | 列挙 | 長さ 8, 4, 2, 1 の連続区間を削除し、結果を shortlex 順に並べる | 余分な選択を取り除く | M1 |
| `zero_chunks` | 列挙 | 長さ 8, 4, 2, 1 の連続区間を 0 にする（結果の shortlex 順） | 複数の値を一度に単純化 | M1 |
| `minimize_individual` | 適応 | 各選択値を 0 に置き換え、だめなら二分探索で最小化 | `x = 1000` → `x = 101` | M1 |
| `delete_spans` | 列挙 | span を丸ごと削除（深い span から） | リストの要素を取り除く | M3 |
| `zero_spans` | 列挙 | span 内の選択をすべて 0 にする | 要素を最も単純な値にする | M3 |
| `sort_spans` | 列挙 | 同じラベル・同じ深さの兄弟 span を選択列の辞書順で並べ替える | `[3, 1, 2]` → `[1, 2, 3]` | M3 |
| `swap_adjacent_spans` | 列挙 | 同じラベルの隣接 span を入れ替える | 部分的な並べ替え | M3 |
| `redistribute` | 適応 | 2 つの整数の選択について、一方を減らし他方を増やす | `x + y > 10` を `x = 0, y = 11` へ | M3 |
| `lower_duplicates` | 適応 | 同じ値を持つ複数の選択を同時に下げる | `x == y` を要する反例 | M3 |
| `simplify_floats` | 適応 | 浮動小数点数の選択を整数値・単純な分数へ寄せる | `1.3927...` → `1.0` | M3 |

`forced` な選択はどのパスも変更しない。

## 予算と停止

| 設定 | 既定値 | 意味 |
|------|--------|------|
| `Settings.max_shrink_evaluations` | 5000 | 縮小中の property 実行回数の上限 |

上限に達した場合は、その時点の最良の選択列で報告し、レポートに「縮小を打ち切った」ことを明記する。

## 品質の検証

`tests/shrink_quality/` に、Hypothesis で既知の最小反例が得られる問題を置き、同等の結果が得られることを回帰テストで確認する（M3）。

| 問題 | 期待する最小反例 |
|------|------------------|
| `sum(xs) <= 1000`（`xs: List[Int]`, 要素 0..1000） | `[1, 1000]`（要素の上限が 1000 なので 2 要素が最短） |
| `x < 1000` | `x = 1000` |
| `len(xs) < 3` | `[0, 0, 0]` |
| `xs` が昇順でない反例 | `[1, 0]` |
| `x + y <= 10` | `x = 0, y = 11` |
| 文字列に `"a"` を含まない | `"a"` |
