# 縮小（Shrinking）

背景は [ADR-0002](../adr/0002-choice-sequence-based-shrinking.md) と [ADR-0008](../adr/0008-functional-core-imperative-shell.md)。

## 目標

失敗する選択列 `s` から、次を満たす `s'` を探す。

1. `s'` で property を実行すると `INTERESTING` になる。
2. shortlex で `s' < s`。

これを固定点（どのパスも改善できない）または予算切れまで繰り返す。
shortlex は整列順序なので、縮小は必ず停止する。

## 評価

候補の評価はランナーが行う（命令型シェル）。

```mojo
def evaluate(candidate: ChoiceSequence) -> Evaluation   # status と実際に消費した選択列
```

- 候補は **再生モード** の `TestCase` で実行する。prefix を使い切った後の選択は 0 になる。
- 採用するのは、評価結果の選択列（実際に消費した分）である。候補より短くなることがある。
- 採用するのは `is_shortlex_smaller(consumed, best)` が成り立つ場合だけにする。候補が短くなっても、実際に消費した列は短lex で大きくなることがある（候補 `[1]` に対し property が常に 2 回 draw するなら consumed は `[1, 0]`）。無条件に採用すると縮小が短lex で上向きに動き、終了の保証が壊れて入力より悪い反例を報告する。
- 同じ候補を二度評価しないよう、選択値の列をキーに評価結果をキャッシュする。
- 既定では任意の `INTERESTING` を採用する（失敗メッセージの一致は要求しない）。

## パスの形

縮小パスは関数型コアに属し、次の 2 種類がある。

| 種類 | シグネチャ（概念） | 例 |
|------|-------------------|----|
| 列挙パス | `(seq, spans) -> List[ChoiceSequence]` の純粋関数。候補を単純な順に返す | 削除、ゼロ化、並べ替え |
| 適応パス | 評価関数 `is_interesting` を引数で受け取る高階関数。二分探索のように前の結果で次の候補が決まる | 個々の値の最小化、値の再配分 |

適応パスも評価関数を注入するだけで、それ以外の副作用を持たない。テストでは評価関数に純粋な述語を渡す。

## パス一覧

上から順に適用し、いずれかが改善したら先頭に戻る。

| パス | 種類 | 内容 | 効果の例 | M |
|------|------|------|----------|---|
| `delete_chunks` | 列挙 | 長さ 8, 4, 2, 1 の連続区間を削除 | 余分な選択を取り除く | M1 |
| `zero_chunks` | 列挙 | 長さ 8, 4, 2, 1 の連続区間を 0 にする | 複数の値を一度に単純化 | M1 |
| `minimize_individual` | 適応 | 各選択値を 0 に置き換え、だめなら二分探索で最小化 | `x = 1000` → `x = 101` | M1 |
| `delete_spans` | 列挙 | span を丸ごと削除（深い span から） | リストの要素を取り除く | M3 |
| `zero_spans` | 列挙 | span 内の選択をすべて 0 にする | 要素を最も単純な値にする | M3 |
| `sort_spans` | 列挙 | 同じラベル・同じ深さの兄弟 span を選択列の辞書順で並べ替える | `[3, 1, 2]` → `[1, 2, 3]` | M3 |
| `swap_adjacent_spans` | 列挙 | 同じラベルの隣接 span を入れ替える | 部分的な並べ替え | M3 |
| `redistribute` | 適応 | 2 つの整数の選択について、一方を減らし他方を増やす | `x + y > 10` を `x = 0, y = 11` へ | M3 |
| `lower_duplicates` | 適応 | 同じ値を持つ複数の選択を同時に下げる | `x == y` を要する反例 | M3 |
| `simplify_floats` | 適応 | 浮動小数点数の選択を整数値・単純な分数へ寄せる | `1.3927...` → `1.0` | M3 |

`forced` な選択はどのパスも変更しない。

## 予算と停止

| 設定 | 既定値 | 意味 |
|------|--------|------|
| `Settings.max_shrink_evaluations` | 5000 | 縮小中の property 実行回数の上限 |

上限に達した場合は、その時点の最良の選択列で報告し、レポートに「縮小を打ち切った」ことを明記する。

## 品質の検証

`tests/shrink_quality/` に、Hypothesis で既知の最小反例が得られる問題を置き、同等の結果が得られることを回帰テストで確認する（M3）。

| 問題 | 期待する最小反例 |
|------|------------------|
| `sum(xs) <= 1000`（`xs: List[Int]`, 要素 0..1000） | `[1, 1000]`（要素の上限が 1000 なので 2 要素が最短） |
| `x < 1000` | `x = 1000` |
| `len(xs) < 3` | `[0, 0, 0]` |
| `xs` が昇順でない反例 | `[1, 0]` |
| `x + y <= 10` | `x = 0, y = 11` |
| 文字列に `"a"` を含まない | `"a"` |
